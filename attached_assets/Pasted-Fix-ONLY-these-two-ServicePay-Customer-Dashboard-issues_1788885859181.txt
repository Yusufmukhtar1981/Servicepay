==================================================

CURRENT CUSTOMER ERROR:

“Microphone access is required to place a call.

The call screen opens but the customer cannot proceed.

Trace the complete ServicePay-to-ServicePay calling flow:

Customer taps Call
→ microphone permission
→ browser/webview permission
→ call session creation
→ signaling/LiveKit or existing call provider
→ ringing
→ answer
→ active audio call

Fix microphone permission handling properly.

Requirements:

1. Before starting the call, check microphone permission.

2. If permission has never been requested:
   request it automatically.

3. If the user grants permission:
   continue the call immediately without requiring the customer to restart the entire flow.

4. If permission is denied:
   show a clear message:

“Microphone permission is required for ServicePay calls.”

Add a button:

“Allow Microphone”

5. If permission is permanently blocked:
   show instructions/button to open browser/app settings where technically supported.

6. On Android Chrome / PWA / WebView:
   handle getUserMedia permission correctly.

7. Use:
   navigator.mediaDevices.getUserMedia({ audio: true })

or the correct existing platform-specific implementation.

8. Detect unsupported browsers/devices and show a proper message instead of failing silently.

9. Release microphone tracks when call ends.

10. Prevent duplicate call sessions when “Call again” is tapped repeatedly.

11. Preserve:
   - block/privacy controls
   - caller/callee identity
   - existing call history
   - secure signaling
   - authentication
